## 🟠 板块 2｜交付闭环：到底有没有人用（14 min｜技术主管主问）⭐核心

> 初试验的是"技术是不是你写的"。**这一轮验的是"做出来的东西有没有真跑起来、被人用、有没有产生结果"**——产品岗和 demo 岗的分界线。

| # | 问题 | 考察点 | 红旗信号 |
|---|---|---|---|
| **Q4** | 三段项目里，**哪一段有真实用户**？多少人？最近一次使用是什么时候？用户是谁？ | 真实使用 ⭐ | "还在开发" / "主要自己测" / 答不上用户构成 |
| **Q5** | Multi-Agent 旅行规划——**代码总量多少行**？一个人写还是有合作？**部署在哪**？能给我个访问地址吗？ | 工程规模 + 可验证 | 说不出行数 / 说"在本地跑过" / 不敢给地址 |
| **Q6** | 你的 50+ Evaluation / Badcase Set——**这 50 个题谁定的**？标准是什么？**有没有一道你两周都没修好**？那道是什么？ | 评测方法学 + 失败分析深度 | "改 prompt 就好了" / 举不出最难的 |
| **Q7** | 营养查询系统用 Codex / AI Coding Agent 写的——**代码有多少是它写的，多少是你写的**？有没有出现过**它写错了你不知道、直接上线**的情况？ | 对 AI Coding 的**真实认知与边界感** ⭐ | "全靠 AI 我不用看" / "我每行都 review"（更可疑） |
| **Q8** | 这项目**从 0 到上线花了多久**？你一个人怎么安排需求、开发、测试、部署？**哪个阶段花的时间最长**？ | 0→1 全流程 | 说不清任何一阶段 / 只做了"写代码" |
| **Q9**（选） | 海康那 3 个月——**你的代码进生产了吗**？还是停在 demo？带你的 mentor 怎么评价你？ | 实习真实含量 | 答"跟着做" / 说不清代码是否上线 |

## 🟣 板块 3｜真实需求现场拆解（18 min｜技术主管 + 老板）⭐核心

> **这一段是本岗位的命门。** JD 写得很直白："对接客户核心人员深挖业务需求，把大白话转成程序逻辑"。现场给一个**真实但不复杂**的题目，看她**先问什么、怎么定边界、怎么验收**。

**给题的统一口径（技术主管念，别让候选人准备）：**

> 场景：领客是一家做留学与语培的公司，运营团队每天发小红书。老板现在提了个需求——
> **"我想要一个能帮我判断一条小红书笔记能不能爆的工具。"**
> 老板自己也没想清楚要什么样，他只说"感觉有些笔记就是写得好"。

| # | 问题 | 考察点 | 红旗信号 |
|---|---|---|---|
| **Q10** | 【第一件事，别写方案】你**第一个问题**会问老板什么？把你要问的问题列 **5 个以上**，写下来。 | **需求澄清习惯** ⭐ | 上来就开始设计功能 / 只问"预算多少" |
| **Q11** | 【第二步】假设老板说不上来，你就自己定。怎么把"感觉写得好"变成**可衡量的东西**？列出你会看的指标和数据来源。 | 指标抽象能力 | 只会说"看点赞收藏" / 说不清数据从哪来 |
| **Q12** | 【第三步】这个工具**第一版做多大**？你砍掉哪些功能？**为什么砍**？ | MVP 边界意识 | 想一次做全 / 说不清砍的依据 |
| **Q13** | 【第四步】**怎么验收**？你说"做完了"，用什么标准证明它做完了、值得用？ | 验收标准 ⭐ | "老板觉得好用" / "我测试过了" |
| **Q14** | 【第五步】这件事**你会怎么写给技术同学**？口头描述一遍那段需求。 | **大白话→技术语言**（JD 核心动作）⭐ | 用术语堆需求 / 说不出结构 |
| **Q15** | 【第六步】这个需求如果交给**外包做**、交给**资深同事做**、交给**一个入职一周的新人做**，分别会怎么做？你怎么选？ | 判断力 + 资源意识 | 只会一种方案 / 答"我都能做" |
| **Q16** | 【延伸】如果试运行一个月，**你会用哪个指标判断这事该继续还是该砍**？ | 数据驱动 + 止损意识 | 说不出单一判断指标 / 只说"看老板反馈" |
